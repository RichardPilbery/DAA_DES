# Restructure as a package, add parameter/scenario import, tests and tutorial documentation

## Headline changes

- **Restructured the model as an installable Python package** (`air_ambulance_des`), with `pyproject.toml`; the old top-level modules and the standalone `visualisation/` folder are removed.
- **Visualisation and results code refactored into classes** (`TrialResults`, `HistoricResults`), moving the plotting logic out of the app and into the package.
- **Parameters can be imported from a spreadsheet template and from predefined scenarios** in the web app, with restore-to-defaults handling.
- **Much larger test suite**, including scenario-import tests, call-generation and resource-allocation tests, school-holiday tests and a backtest against a stored baseline.
- **New Quarto documentation site** with tutorials for five audiences (advanced contributors, intermediate users, decision-makers, domain experts and the general public).
- **Project housekeeping**: devcontainer, citation file, code of conduct, STARS/STRESS-DES checklists and expanded READMEs.

## Package restructure

- Moved `class_ambulance`, `class_hems`, `class_hems_availability`, `class_patient`, `des_hems`, `des_parallel_process`, `distribution_fit_utils` and `utils` into `air_ambulance_des/`, with an `__init__.py` that exposes the modules and sets version and authors.
- Added `pyproject.toml` (setuptools, v0.1.0) and updated `requirements.txt` to install the package.
- Added a separate `app/requirements.txt` for Streamlit, plus `packages.txt` for the Quarto install on Streamlit Community Cloud.
- Removed unused or superseded files (`OLDpackages.txt`, root `utils.py`, the `visualisation/` folder, a stray `.quarto_ipynb` and old autogenerated docs).
- Updated the container, the pdoc workflow command and import paths in the app and tests to match the new layout.
- Renamed `code_documenter` to `code_compressor` and updated its config for the new structure.

## Model changes

- **Servicing schedules**: corrected the Airbus H145 schedule in the service schedule files.
- **School holidays**:
  - New `school_holidays.py` module for parsing holiday dates. It is more robust to UK (dd/mm/yyyy) and ISO formats.
  - Fixed an incorrect holiday end date.
  - Extended holiday coverage to the end of 2027.
- **Helicopter benefit**: adjusted when the check for whether heli benefit is known takes place.
- **Zero-call days**: fixed handling of days when the number of calls is zero.
- **Availability data**: daily availability data is now assigned to a class attribute and passed through `TrialResults`.
- **Sequential runs**: changed how run results are saved when executing sequentially rather than in parallel.
- **Default files**: added `*_DEFAULT.csv` copies of the key `actual_data` files (school holidays, service schedules, upper allowable time bounds) so edits made through the app can be reset.

## Web app

- **Parameter import**: the app can read a filled-in parameter template (`app/inputs/parameter_template.xlsx`, expanded considerably) and write the values into the model input files.
  - Import logic is in `app/setup.py`, with supporting changes in `_app_utils.py` and `_state_control.py`.
  - Paths are less fragile, uploaded values are validated, and parameters can be restored to defaults.
  - The template download works again.
- **Predefined scenarios**: users can choose from scenarios in `scenarios/` (24 hour running, 24 hour CC running, Extended CC coverage, Two EC145).
- **Visualisation refactor**:
  - Replaced the old function-based calculation modules with class-based results objects.
  - Restored all plots on the key visualisations, historic comparison and debugging tabs.
  - Fixed the Quarto report template.
- **Streamlit Community Cloud fixes**: path handling, CSV loading across platforms, a Quarto import issue and an indexing bug. The temporary debugging output added along the way has been removed.
- **Housekeeping**: cached data is cleared on app rerun, the Streamlit version is bumped, and app text and READMEs are updated (welcome, info, glossary, acknowledgements).

## Testing

- **Test fixtures and markers**: `conftest.py` and `helpers.py` updated, and `pytest.ini` added with markers. `tests/README.md` documents how to run each group.
- **New test files**:
  - `test_scenario_importing.py`: the parameter template and predefined scenarios.
  - `test_school_holidays.py`: date parsing and plausibility of holiday files.
  - `test_call_generation.py`: including zero-call days.
  - `test_resource_allocation.py`: which resource is sent to a patient.
  - `test_backtest.py`: results of a fixed scenario and seed against the stored baseline in `tests/backtest_baseline/`.
- **Existing suites** (unit, reproducibility, against reality, against condition changes) updated for the package structure.
- **Linting**: all files linted with `ruff`.

## Documentation

- **Quarto site** in `air_ambulance_des_docs/`, with the required extensions, themes, sync script and `_publish.yml`.
- **Tutorials** under `air_ambulance_des_docs/tutorial/`, generated and then edited per audience:
  - `advanced-contributor`: 8 chapters, glossary and index.
  - `intermediate`: 8 chapters, glossary and index.
  - `stakeholder-decision-maker`: non-technical pages on what the model does, how it works, risks, assumptions and questions to ask.
  - `stakeholder-domain-expert`: non-technical pages, including how decisions are made and how to read results.
  - `stakeholder-public`: plain-language pages, including how data is used.
  - The folder also holds the generation records (`_outline.yaml`, `_evidence.yaml`, `_generation.json`, style guides) used to keep tutorials updatable.
- **Reference docs**: updated the pdoc workflow command in `.github/workflows/docs.yml` and `.gitignore` for the new structure.
- **READMEs**: rewrote the top-level README and added or expanded READMEs for the app, `actual_data`, `historical_data`, `external_data`, `scenarios`, `tests` and the app inputs.

## Notes for reviewers

- The diff is large (~200 files). Most of it is generated or moved content:
  - Vendored Quarto extensions in `air_ambulance_des_docs/_extensions/`.
  - Tutorial pages and their generation records, e.g. `_generation.json`.
  - `code_compressor/output_py/repo_content_*.txt`.
  - Backtest baseline CSVs.
  - Files moved into `air_ambulance_des/`, which show as renames.
- Suggested review order: `air_ambulance_des/` and `app/setup.py`, then `tests/`, then the docs.
- `air_ambulance_des_docs/_quarto.yml.pre-tutorial.bak` is a backup of the config from before the tutorial was added. It can probably be deleted.
- The very slow tests (`test_against_reality`, `test_against_condition_changes`) run long simulations. `pytest -m quick` or the seconds-long files listed in `tests/README.md` are a good first check.
- Backtest baselines will need regenerating whenever the model's results change intentionally (see `test_backtest.py`).
