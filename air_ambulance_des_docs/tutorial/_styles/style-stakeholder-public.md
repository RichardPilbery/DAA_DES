# Style block: stakeholder-public

- **max_code_block_lines**: 0 (no code at all)
- **max_diagram_participants**: 8 (boxes in a flowchart; no sequence, class or state diagrams)
- **uses_evidence**: true. Limitations are translated into plain language, with no issue numbers in body text.
- **page_plan**: true. Use the page set from `stakeholder.md`, not the chapter list.
- **Reader**: Lay readers and members of the public (for example people living in Devon, supporters of the air ambulance charity, or anyone curious) who want to understand what a computer simulation of the air ambulance service is, what it does with information, and how to read what it produces. No technical or clinical background assumed.
- **Tone**: plain English, short sentences, active voice, British English, and an "In brief" callout at the top of every page. Simplest language: aim for a reading age of about 12 to 14. Second person ("you"). Reassurance only where the code backs it up. Honest about what the code doesn't show. No internal team concerns. Never state or imply legal compliance.
- **Analogies**: everyday ones, where they help. Never as a substitute for a fact.
- **Emphasis**: what the simulation is for and what it produces; what it does with information, listing only personal data the code visibly handles and saying clearly what couldn't be determined; how to read its results and the common misreadings; what it assumes and where it can be wrong.
- **Length**: roughly 300 to 600 words per page.
- **Quarto features**:
  - "In brief" callouts, tables and simple flowcharts.
  - Value boxes for a few key facts (if enabled).
  - `[term]{.key-term}` highlighting (if enabled).
  - No tabsets with code, no code annotations and no line highlighting.
- **House notes**: none beyond the above.
